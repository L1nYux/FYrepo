# 长文等待超时紧急热修

适用服务器 0.4.2 / 0.4.4，兼容已经安装的 32768 输出上限热修。

## 修复内容

- 非流式模型推理使用独立 240 秒网络等待；价格、额度、模型发现等短请求保持原来超时。
- Gunicorn 等待 300 秒，退出宽限 270 秒；Nginx 代理读取等待 360 秒。
- 安装和升级模板同步修改，后续升级不会回到 60 / 120 秒。
- 上游 400 / 404 / 422 错误只提取参数名、白名单错误类型及数字约束；不返回或记录上游原文、输入、认证头和密钥。
- 新的失败记录保存实际耗时，并返回调用编号，便于核对厂商账单。
- 不改输出上限、额度、API Key、已有调用及费用状态；不自动重试可能已计费的请求。

## 安装

使用发布资产 `inference-timeout-hotfix.py`，不能直接运行仓库里的未打包模板。
安装脚本核对现有代码哈希及实际 Nginx / Gunicorn 配置，备份后修改。
会等待现有推理请求结束再短暂重启应用；若仍有请求运行则恢复并退出。
失败自动恢复原文件和配置。无数据库迁移，不回滚数据库，不发送付费推理。

成功标志：`HOTFIX OK: inference=240s; Gunicorn=300s; Nginx=360s`。
备份在 `/var/backups/research-workbench/inference-timeout-*`。

## 费用与 MiniMax 422

默认只读导出关联实验 `EXP-A530E6481A72` 的调用到备份中的
`billing-review.json`，包含调用编号、时间、模型、状态及预留额度，不含输入与密钥。
可用 `--experiment EXP-编号` 指定其他实验。
费用待核对的记录需要管理员依据厂商账单执行现有核对功能；本热修不会猜测费用或释放预留额度。
旧 422 的响应体已经被旧代码丢弃，不能事后还原；新请求失败时会有脱敏参数诊断。
422 的根因需要依据新诊断确认，不能仅凭状态码确定是 token 或 temperature。

## 调用端

继续使用原 HTTP 地址与 `stream=false`；客户端等待时间建议至少 360 秒。
240 秒是网络等待设置，不能保证上游模型一定在此时限内完成。
供应商自身超时或额外代理的限制仍需由对应管理员核实。
公开接口本次未新增 SSE。

仅完成静态语法与发布资产完整性检查，未执行付费模型调用或自动化测试。
