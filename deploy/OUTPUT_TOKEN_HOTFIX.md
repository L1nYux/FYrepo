# 输出上限紧急热修 · 2026-10-09

适用于服务器 0.4.2 或 0.4.4。桌面客户端无需重装。

- 读取模型时保留厂商报告的较小上限，超过 2048 的上限不再被错误压低。未报告上限时默认为 32768；目前平台配置最高为 32768。
- 新手动添加的模型默认 32768，字段迁移不直接改已有模型的数据。
- 普通调用接口保留截断状态：长度截断为 `finish_reason: "length"`，内容过滤为 `content_filter`；未知或缺失状态不伪装为 `stop`。
- `/api/pool/v1/models` 增加 `max_output_tokens`。超限错误给出当前配置上限。
- 单独的服务器修复脚本将所选团队中已启用、连接已启用且上限恰好为旧默认 2048 或 8192 的模型改为 32768。其他已有上限保留。

发布资产 `output-hotfix.py` 内嵌修复文件及完整性信息。它确认运行目录、版本和原文件哈希，先列出目标模型，停止应用及正在运行的相关定时任务，备份源文件和 SQLite 数据库，再安装代码、执行字段迁移及模型配置更新。应用健康检查失败会恢复代码与数据库。记录存放在 `/var/backups/research-workbench/output-hotfix-*`，目录仅 root 可读。

只有一个活跃团队 API 池时自动选择；多个池时在任何修改前退出，并列出 workspace ID。使用 `sudo python3 /tmp/zhiyu-output-hotfix.py --workspace ID` 可指定目标。

脚本不调用厂商模型，不读取或打印厂商密钥，不调整用户额度、余额、价格或调用记录。上游模型自身的能力限制仍由厂商决定。完整正文需要调用方检查 `finish_reason`；已有截断结果不能通过配置修改自动补全。

这是服务器热修，正式桌面更新渠道仍为 v0.4.4。静态语法与包完整性在打包时检查；未进行付费模型调用或手机/桌面界面测试。
