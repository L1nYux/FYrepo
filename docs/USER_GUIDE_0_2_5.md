# 功能与使用说明书

适用版本：0.2.5（迁移至 core `0017`），包括统一邮箱验证码找回、财务回收站与手机页面适配。本地版入口见 `desktop/README.md`。

## 1. 页面怎么分

### 访客页面

打开首页默认进入访客展示页。访客可以查看已公开项目简介、已公开实验及其附件、成员自愿公开的资料，以及「联系我们」。空的展示栏目按页面内容隐藏，不填充虚构数据。

右上角「登录 / 注册」打开弹窗。注册填写账户名、密码及管理员分发的邀请码。管理员和开发者使用同一登录入口，权限由账号确定。

「联系我们」展示管理员填写的邮箱、电话、GitHub、其他联系方式及合作说明；当前没有对外留言或合作申请表单。

### 内部工作台

- 顶部：切换「工作台 / 消息」，查看未读提示，打开右上角账户菜单；最右侧是深色 / 浅色主题开关。
- 工作台：公告栏、项目管理、实验库、财务服务；侧栏可展开当前项目的任务层级。
- 账户菜单：账户设置、公开资料、修改密码、退出登录；管理员另有团队管理入口。
- 账户设置页分「账户资料」与「密码与安全」两栏；「密码与安全」里既能用旧密码改密，也能在不记得旧密码时用邮箱验证码重置。主题不在这里切换，用顶部开关（选择只保存在当前浏览器）。
- 页面通过页签及折叠区分内容，项目页分「概览 / 任务 / 成果」，财务分「团队账本 / 报销申请」。

## 2. 角色与权限

项目负责人是在某个项目中的职责，账号仍属于开发者或管理员；比赛负责人也是独立职责。

| 操作 | 开发者 | 项目负责人 | 管理员 |
| --- | --- | --- | --- |
| 查看内部项目与任务进度 | 可以 | 可以 | 可以 |
| 项目、任务留言 | 可以 | 可以 | 可以 |
| 创建项目、任命项目负责人 | 不可以 | 不可以 | 可以 |
| 创建 / 编辑母任务 | 不可以 | 本项目可以 | 可以 |
| 创建子任务 | 本项目成员可以 | 本项目可以 | 可以 |
| 编辑已有任务、删除 / 恢复任务 | 不可以 | 本项目可以 | 可以 |
| 提交任务成果、更新进度 | 本项目中被分配的任务 | 本项目可以 | 可以 |
| 子任务结项 / 重新打开 | 被分配的子任务可以 | 本项目可以 | 可以 |
| 审核任务成果、处理母任务结项 | 不可以 | 本项目可以 | 可以 |
| 项目最终结项、选用最终成果、删除 / 恢复项目 | 不可以 | 不可以 | 可以 |
| 查看团队账本、提交本人报销 | 可以 | 可以 | 可以 |
| 查看报销申请详情（含他人待审申请与凭证） | 可以 | 可以 | 可以 |
| 审批报销、直接记账、编辑 / 作废账目 | 不可以 | 不可以 | 可以 |
| 任免成员、停启账号、分发邀请码、发布公告 | 不可以 | 不可以 | 可以 |
| 忘记密码：邮箱验证码重置（登录页及账户设置） | 可以（需账号已填邮箱） | 可以 | 可以 |

成果的可见性与任务进度不同：作者、管理员及项目成员可看本项目的全部成果；其他开发者可看已通过或已选为最终成果的内容。

已有旧版普通用户保持受限账号，不能进入新版内部工作台或消息区。新版关闭普通用户自由注册与手动登录身份切换。

### 忘记密码

登录页与「账户设置 → 密码与安全」使用同一套流程：

1. 未登录时输入用户名或已绑定邮箱；已登录时直接使用自己的绑定邮箱。
2. 点击「发送验证码」，检查收件箱及垃圾邮件。页面上直接填写六位验证码、新密码和确认密码，点击「验证并重置密码」。
3. 验证码 10 分钟内有效，最多尝试 5 次；重发冷却 60 秒，每个账户每小时最多发送 5 次。只有最新验证码可用；密码不合规时可在原页修改，正确验证码不会因此消耗次数。
4. 未登录时成功后返回登录；已登录时当前设备保持登录，其他设备上的旧登录失效。

手机端使用独立单列页面，可粘贴验证码，按钮和输入框适配触屏，键盘弹出后仍可滚动提交。桌面登录页在系统浏览器打开当前团队服务器的找回页面，重置后回到桌面版登录。

未填写邮箱的旧账户仍可用用户名登录和保存资料。桌面头像及「账户资料」旁显示小红点，绑定后消失，不强制弹窗。没有可用邮箱时，请管理员核实身份后协助重置。邮箱保存时转小写且唯一，可以同时作为登录名；注册和绑定邮箱的归属验证码确认暂未加入。

匿名找回页面统一提示「如果该账户已绑定可用邮箱」，不透露账户是否存在。已登录时发信失败会明确提示重试；开发模式的验证码只输出到服务端控制台，不会真的发送邮件。收不到邮件时检查账户邮箱、垃圾邮件及 SMTP 服务日志。

财务账目允许管理员编辑或删除；成员可以删除自己的待审报销。删除后进入回收站并从余额、支出与项目成本统计中移除，恢复后重新计入。关联报销与账目同步处理。管理员在回收站可彻底删除，先显示关联范围，再弹窗确认；默认选择取消，确认后无法恢复。

## 3. 管理员的初始设置

1. 在右上角「团队管理」进入邀请码管理，生成邀请码并分发。成员注册后成为开发者；注册时会要求填写邮箱。
2. 进入成员管理，按需升降管理员权限、启用或停用账号；不能自行修改自己的账号状态。
3. 填写团队联系方式；成员在「公开资料」填写公开姓名、研究方向、简介、GitHub，并自行决定是否公开。
4. 发布公告，创建项目。项目名称必填，目标、负责人和成员可在补充信息中设置，负责人默认创建者。
5. 确认服务器已配置 SMTP（见[运维说明](MAINTENANCE.md)），否则成员无法自助找回密码。`manage.py check` 会在生产环境缺 SMTP 时给出 `core.W001` 警告。

仅拥有服务器 SSH 权限不会自动获得网站管理员权限；网站权限由账号管理。

## 4. 项目、任务与成果

### 三层结构

项目表示长期方向；母任务表示一阶段目标；子任务表示具体可执行工作。任务支持负责人、多名协作成员、DDL、描述与进度。

项目可以由管理员填写预算，并在项目页看到成本汇总（见第 7 节的「项目成本汇总」）。

任务类型可以选「实验设计 / 实验过程 / 结果分析 / 其他事务」。类型用于分类，不另加审批环节。创建子任务时默认继承母任务的类型及比赛关联，可以修改。

### 推荐操作顺序

1. 管理员建立项目并指定负责人。
2. 项目负责人建立母任务、说明预期成果和 DDL。
3. 项目成员在母任务下拆分子任务并分配成员。
4. 执行者在任务内留言，记录思路、问题及结论；提交成果时选择文字、文件、源码链接或实验记录。
5. 子任务执行者可自主结项；母任务成果交项目负责人审核。退回修改须填写原因。
6. 管理员选用有价值的成果并决定项目最终结项，可以在分支尚未全部结束时选取最终成果。

提交不要求附件，一句话或纯文本也可以，但必须提供实际成果内容。已结项任务若要继续提交，先重新打开。任务中的留言与成果按时间显示，便于追溯讨论上下文。

新建任务只需填写标题；负责人默认项目内的创建者，创建者不在项目时默认项目负责人。其他字段可选。任务提交只突出正文与附件：子任务默认「提交并结项」，母任务默认「提交审核」；若仅保存阶段成果，可在更多选项中取消结项勾选。关联实验、源码链接和同时存入实验库也放在更多选项中。

### 删除与恢复

删除为隐藏记录并保留数据。删除项目或母任务后，其下级分支一并不可访问；恢复下级任务前需先恢复项目与母任务。回收站入口位于管理区域；管理员可恢复项目，管理员或本项目负责人可恢复任务。

## 5. 比赛

进入项目管理的「比赛」页签。管理员创建比赛并指定负责人，可填写截止日期、官网链接、要求及说明；比赛负责人可编辑自己负责的比赛，修改负责人由管理员操作。

任务可选关联一个比赛，不关联时仍正常推进项目。同一比赛可汇集不同项目中的关联任务。比赛详情分「关联任务 / 参赛成果」；管理员从关联任务的成果中选用参赛成果。

管理员可归档或恢复比赛。归档保留任务关联及已选成果，恢复后可继续管理。比赛不会创建额外的任务审批流程。

## 6. 实验库

### 与任务的分工

任务负责「谁做什么、做到哪里、提交什么、是否完成」；实验记录负责「如何进行、条件是什么、得到什么结果」。实验记录不重复设置任务进度和结项流程。

### 记录内容

- 文件或文字：已有 Word、Excel、PDF 等实验记录可直接上传，无需重新填写文件里的内容；也可以仅写自由文字。
- 名称：可选，留空取第一个文件的名称或正文第一行；编号自动生成。
- 项目：可选；从任务中新建时自动关联项目及来源任务。
- 参数：可选的「参数名 / 值」，例如样本量、设备、温度、模型或评价方法；最多 40 项，参数名须唯一。
- 附件、源码 / 材料链接、版本标识：按需添加。

记录形式适用于 LLM、问卷、设备测试等不同实验。补充信息默认折叠；旧记录中已有的目的、过程、结果、数据来源、批次、模型、Prompt、人工审核字段保留，在有值时继续显示和编辑，新记录不再提供整套结构化表单。

### 从任务提交实验

提交成果时可以引用已有实验，也可以勾选将本次文字与文件同时存入实验库。新记录直接复用提交内容，自动关联当前任务及项目，并由这份成果引用，无需再填写一遍实验表单。

### 参数模板与对照

填写参数后可命名并保存模板，全体团队可选择复用；同一创建者保存同名模板会更新参数。创建者和管理员可删除模板，已创建的实验不会随模板删除。

实验库支持名称 / 编号等搜索、筛选自己的记录、选择 2–3 条进行只读对照。对照不会自动评分或生成分析结论。

### 公开审核

状态为「内部 → 待公开审核 → 已公开」。创建者或所属项目负责人可申请，管理员批准或转回内部。公开前必须填写方法与条件、实验结果；已公开记录修改后重新进入待审核。

**实验记录一旦公开，其实验附件也允许访客下载。** 管理员发布前应检查本条记录及其附件内容。任务成果附件不会因为引用了公开实验而自动公开。

## 7. 财务服务

### 团队账本

全部开发者可查看团队账本、余额、收入与支出合计、账目说明及凭证。管理员直接记账，类型包括收入、支出、奖金、API 成本、报销入账。记账时可选关联一个项目；账目可编辑或作废。

余额与收入 / 支出合计按**未作废的全部账目**统计，不受账本列表一次显示多少条影响；作废记录对管理员仍然显示在列表里，但不计入余额。账本列表按发生日期倒序显示最近记录。

### 报销申请

成员在「报销申请」填写金额与事由，可选凭证；日期默认今天，关联项目可选。**报销申请对全体团队成员可见**（含他人正在待审、已驳回的申请及其凭证和审核结论），与团队账本的口径一致；普通用户与访客看不到。管理员看到全部申请并通过或驳回，驳回须有原因。

「关联项目」是可选项，点开下拉框选择一个项目即可把该笔报销归到项目名下；留空（「不关联项目」）表示与具体项目无关的团队公共开支。下拉框只列出**本人参与的项目**（本人是负责人或成员），管理员可以选择任何未删除的项目；选择其他项目不会被接受。列表中的「项目」一列显示归属，未关联的显示「未关联项目」。

通过后自动产生报销入账记录，**并把报销关联的项目带入账本记录**，凭证同步到账本；**入账后的账目及凭证按团队账本规则对开发者可见**。

### 项目成本汇总

项目页「概览」页签有「成本汇总」一栏，汇总**关联该项目且未作废**的账本记录：

- 已用（支出）：支出、奖金、API 成本、报销入账的合计。
- 项目收入：关联该项目的收入类账目合计。
- 项目预算：管理员在项目设置里填写的预算，可留空。
- 预算剩余与使用比例：只在设了预算（且不为 0）时显示；超出预算会标注「已超出预算」，进度条封顶 100%。

下方列出关联的账本记录（最多 20 条，按发生日期倒序）。所有开发者都能看到这一栏，与账本可见性一致。没有关联项目、或已作废的账目不计入。

本版没有自动支付、银行对账、财务修改版本历史或网站操作审计模块。

## 8. 消息与内容引用

顶部「消息」是独立沟通区域，包含团队公共讨论与成员私聊。公共讨论供开发者及管理员使用；私聊页面与私聊附件仅参与双方可查看，管理员不会凭管理员身份看到其他两人的私聊。

支持文字、文件、红色未读提示及成员在线状态。打开会话并实际看到底部消息后才标记已读，后台轮询不清除未读。在线状态约每 10–12 秒更新，90 秒没有前台心跳会显示离线。Enter 发送，Shift+Enter 换行；输入法组词时回车不会发送。旧公共聊天室历史保留，有历史内容时提供兼容入口；旧普通用户可访问的历史公共聊天室请勿用于敏感讨论。

### 「＋」引用操作

1. 点击输入框旁的「＋」。可选上传附件，或引用任务、实验、财务、公告。
2. 选择类型，搜索标题、实验编号、财务说明或报销事由。
3. 选择结果，输入框上方出现已选引用，可用「×」移除。
4. 输入消息后发送，也可直接发送引用卡片。每条消息最多 5 条引用。
5. 接收者点击卡片进入原任务 / 实验详情，或公告 / 财务只读详情页。

### 权限与更新

引用保存原记录的链接关系，不复制全文，也不授予权限。财务搜索包含团队账目和全部报销申请（团队成员都能看到报销申请）。

原记录编辑后，重新加载聊天显示最新标题和状态；没有权限、原记录已删除或公告已撤下时，只显示不可用提示，不显示原标题、金额或原记录编号。报销申请对团队成员本身就是公开的，因此引用他人的报销不会额外暴露信息；对团队以外的人（未登录访客、普通用户）则一律不可见。

聊天适合即时沟通。重要决定仍应由成员写回任务留言；当前没有自动转成任务留言、转发、撤回、消息全文搜索或群组管理。

## 9. 文件和源码链接

上传支持 TXT、PDF、Word、Excel、Markdown、图片、CSV、ZIP 以及常见源码 / 配置文本格式。图片包括 PNG、JPG/JPEG、GIF、WebP、BMP；源码包括 Python、Notebook、JS/TS、R、Shell、SQL、JSON、YAML、TOML 等。

每个上传字段单次最多 5 个文件、单文件 20 MB、合计 40 MB；任务成果同时存入实验库时复用该份附件。文件保存及下载，不在服务器执行、不自动解压，也不提供在线 Word / Excel 编辑器。

GitHub 当前以源码链接和版本标识关联记录。尚未接入 GitHub 自动同步仓库、branch、commit、tag 或实验执行服务。API 密钥使用服务器环境配置或团队密钥管理方式，不写进记录、聊天、源码附件或公开仓库。

## 10. 数据与记录原则

实验保存实验本身；任务留言保存成员主动提交的讨论；消息保存聊天内容及未读状态。在线状态只保存每个账号最新一次心跳，不积累历史。本版没有网站业务操作审计、访客行为统计或实验自动运行记录。服务器系统服务日志由运维工具管理，不进入实验库。

本版调试覆盖后端权限、验证码找回、会话失效、财务统计及回收站，以及 Electron 实际页面的跳转、主题、手机宽度和删除弹窗。具体结果见 `RELEASE_0_2_5.md`。服务器需升级对应源码后才会启用新业务功能。
