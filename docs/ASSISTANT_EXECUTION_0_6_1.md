# 助手执行基础：保存进度，简化使用

2026-10-11。沿用 `HARNESS_REVIEW_0_6_1.md` 中归档的 Codex / DeepSeek Harness 源码研究，实现适合知域现有 Django、SQLite 和小服务器的第一批执行基础。没有引入这些项目作为运行依赖。

## 用户看到的变化

- 正常使用仍是发送、停止和查看结果；已授权范围内的每项操作不再另加确认步骤。
- 运行中可发送补充要求，按顺序在下一模型步骤处理。发送响应丢失时用同一凭据确认已有记录；刷新恢复追加状态，停止前尚未处理的要求明确标记。
- 等待只显示排队、处理或回复。完成后显示简短结果状态，输入栏不再堆叠调用次数、tokens 和金额；用量在原有 API 池查看。
- 可恢复的错误显示「继续」，沿用原任务和消息；网络断线显示「重新连接」，只读取已有任务，不重新提交消息。
- 上游回复未保存且费用未确认时暂停调用，暂不提供重试按钮。核对完成后可重新打开对话重试。

## 实现

| 部分 | 做法 |
| --- | --- |
| 任务队列 | 输入、模型选择、资金来源和执行选项先写入数据库。服务器的 `assistant_worker` 在网页进程之外执行；本地桌面保留两个线程并持续扫描同一队列 |
| 领取与续租 | 条件更新领取，120 秒租约，20 秒续租。检查点、进度与业务写入检查同一执行令牌，失去执行权的旧线程不能覆盖新结果 |
| 步骤保存 | 准备、模型请求、已保存回复、每个工具结果和最终回答分别保存。原生工具 ID、推理字段和供应商签名在当前轮次中保留 |
| 过程记录 | `AssistantEvent` 按任务递增序号记录边界，与检查点一起提交。接口只返回序号和事件种类，不暴露内部提示或工具参数；刷新后仍以已保存状态呈现 |
| 补充要求 | `AssistantInput` 按任务记录序号及重复请求凭据。接收、应用、停止丢弃与最终保存使用任务写锁，已接受的要求不会因同时完成而静默消失 |
| 本地写入 | 继续使用共享业务命令和事务回执。恢复相同参数的操作复用回执，写入仍重新检查项目、成员、插件、授权、版本及取消状态 |
| 费用 | `Call` 账本单独保留。预留成功后保存调用 ID，再请求供应商。未知费用不自动重发；显示的用量汇总来自账本，不依赖线程中尚未保存的计数 |
| 备用连接 | 助手接入同一团队路由与共享健康状态，步骤预留回调保存真实调用。各次尝试归入任务编号；后续轮次使用实际连接，有供应商签名的上下文不跨连接切换 |
| 上下文 | 历史保留完整用户轮次及成对工具请求/结果。超出字节预算时裁掉较早整轮、保留已提交操作回执，并缩短只读资料正文；不截断 JSON，不压掉当前原生工具配对或写入回执 |
| 取消 | 停止后不启动新的工具；对尚未执行的原生请求记明确的未执行结果，已提交操作保留。正在进行的模型请求沿用既有结算逻辑 |

队列不再因两个执行槽都忙而拒绝接受消息。同一账户仍一次执行一轮，数据库锁保护重复提交。每次最多连续 32 个模型步骤，达到边界保存进度；继续时重置这一窗口，不重置用量或授权操作计数。

图片在检查点中只保存所属账户的图片 ID，实际请求前读取图片数据；结束的任务只保留本轮消息，避免把整段历史和图片反复复制到每个任务中。

### 重启恢复规则

1. 过期租约处于准备、下一请求之前、工具处理或最终保存阶段时，领取者从保存的步骤恢复。
2. 模型请求阶段没有保存完整响应时，自动恢复会停止。账本已结算也不能凭空重建丢失的响应。
3. 已提交写入之后、工具结果保存之前中断时，使用原请求参数和操作组读取事务回执。它只保证相同参数重放，不保证不同参数表达的语义重复操作。
4. 过期或撤销的授权不会因恢复而重新生效。用户可在已有授权入口选择同一项目的有效授权后继续。
5. 旧任务没有新格式的执行记录；保留已有对话和用量，不伪造历史工具调用或恢复点。

## 部署与边界

新增迁移 `aihub/0026_assistant_execution.py`、`aihub/0029_assistant_inputs.py`。安装及保留数据升级脚本安装 `research-assistant-worker.service`；升级会先停止旧 worker，备份其配置，回滚时恢复原服务配置和启用状态。生产数据库与远程服务尚未更新，交付状态以本批完成说明为准。

手动部署时，设置 `WORKBENCH_ASSISTANT_WORKER=external` 并运行 `python manage.py assistant_worker`。开发默认 `inline`；桌面本地服务在迁移后启动队列扫描。单独使用开发网页服务器时，请求/重新连接会触发队列领取。

这是步骤检查点和有序过程日志，尚不是可仅凭事件重建所有 token 的完整事件系统。上下文采用明确标记的确定性裁剪，尚无供应商 tokenizer、语义摘要或模型窗口自动发现。原要求和本轮所有补充属于同一裁剪单元，保留原生工具请求/结果与回执。第三方插件生命周期和 MCP 适配仍未实现；现有三种业务写入工具范围没有扩大。
