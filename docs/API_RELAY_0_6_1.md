# 知域 0.6.1 API 接入

## 使用

团队负责人在“连接与模型”保存上游地址和密钥，启用模型并登记有效价格。成员在“额度与用量 → 我的 API Key”生成自己的 Key。

其他软件填写：

- Base URL：`https://你的知域域名/v1`。
- API Key：成员生成的 Key；完整值只在生成时显示，服务器存储其哈希。
- 模型：复制页面或 `/v1/models` 返回的模型 ID；形如 `供应商编号/原始模型ID`，用于区分同名模型。
- 接口类型：OpenAI 兼容 Chat Completions。项目、实验关联均可省略。

Key 的页面默认有效期为 30 天；高级选项可以设置长期有效、模型范围和累计费用上限。每位成员有效 Key 数量默认 10 个，管理员可在“团队额度 → 调用限制”调整，0 表示不额外限制。撤销、账户暂停、成员资格失效或团队解散后不能继续发起调用。

页面提供 Python SDK、Python 标准库和 curl 示例，也可切换流式输出。SDK 示例关闭自动重试。若上游响应中断，先查调用编号对应的账目，避免重复发起收费请求。

## 接口

| 方法 | 地址 | 内容 |
| --- | --- | --- |
| GET | `/v1/models` | 当前 Key 允许且已配置的模型 |
| POST | `/v1/chat/completions` | 对话与函数工具调用；`stream: true` 返回 SSE |
| GET | `/v1/key` | 当前 Key 的有效期、模型范围、累计费用、预留及本人额度 |
| GET | `/v1/usage` | 当前 Key 的调用账单；可带 `call_id` 或 `page`，每页 50 条 |

以上地址同时保留 `/api/pool/v1/` 前缀的旧入口。已有实验运行记录接口保持不变。

鉴权使用 `Authorization: Bearer YOUR_API_KEY`。有效请求无需浏览器登录；浏览器 Cookie 不改变 API Key 对应的成员或团队。

用量响应包含 token、缓存与推理用量、费用、价格版本及调用状态。调用编号同时放在 `X-Request-ID`；非流式结果的 `workbench` 字段包含团队及可选的项目、实验归属。查询不返回提示词、工具内容或上游密钥。升级前的调用没有 Key 归属，仍在原团队账单中保留，不会猜测其所属 Key。

模型调用使用数据库共享限流。原有团队默认保持账户每分钟 60 次、同时 3 个调用，每个 Key 每分钟 30 次、同时 2 个调用；管理员可在“团队额度 → 调用限制”分别调整，0 表示不额外限制。成员和 Key 限制同时生效，多个 Key 不绕过成员总限制。模型与账单查询不占用推理并发槽位。`/v1/key` 返回当前限制。

## 请求体与上下文

中转请求体和序列化的消息/工具上下文默认各为 **16 MiB**，分别用 `WORKBENCH_RELAY_MAX_REQUEST_BYTES` 和 `WORKBENCH_RELAY_MAX_CONTEXT_BYTES` 配置。单条文本不再单独卡在 10 万字符；默认允许 1024 条消息、128 个工具定义，可用 `WORKBENCH_RELAY_MAX_MESSAGES` 和 `WORKBENCH_RELAY_MAX_TOOLS` 调整。这些是传输和内存保护边界，不是模型 token 上下文窗口，不拆分或截断输入。

超出配置返回 HTTP 413，响应提供 `max_bytes`、`received_bytes` 和 `X-Request-Body-Limit`，不发起上游调用、不产生费用。配置需要同步 Django 与反向代理；示例 Nginx 上限为 64 MiB。请求体可配置范围为 64 KiB–64 MiB。

最大输出由具体模型配置决定，模型配置允许最高 1,048,576 tokens；历史模型设置保留，上游仍需实际支持所填值。推理响应默认最多 16 MiB、单条 SSE 行默认最多 4 MiB，分别可通过 `WORKBENCH_INFERENCE_MAX_RESPONSE_BYTES`、`WORKBENCH_INFERENCE_MAX_EVENT_BYTES` 配置。价格与目录查询保留独立的小响应上限。

## 备用连接与故障恢复

负责人编辑模型，在高级设置中选择一个备用连接下的同名、同协议模型。默认没有备用连接，每次请求最多尝试两个连接；不会继续追随备用模型自身的配置。备用模型仍需启用、配置密钥和有效价格，支持请求的输出上限及工具；限制模型的 Key 必须同时允许该备用模型。

- DNS 失败、HTTP 401/403/404/429 且账本已确认为零费用失败时，释放本次预留后才尝试备用连接。HTTP 400/422 的参数错误不自动切换。
- 网络中断、超时、HTTP 5xx、响应解析失败、缺少用量和已输出部分内容均不自动重发。结果不明的尝试保留预留等待核对。
- 每次实际尝试独立预留并按所用连接的价格版本结算。备用价格超过成员、团队、Key 或单次限额时拒绝发送，不通过切换绕过额度。
- 响应和 `X-Request-ID` 使用首次实际尝试的稳定编号；`workbench.call_id` 指向最终尝试，`attempt_count` 是实际尝试数。`/v1/usage?call_id=请求编号` 返回当前 Key 的整组尝试；每行也包含 `request_id`。历史未分组调用仍按原编号查询。

连接故障状态保存在数据库，网页进程共享。五分钟内连续三次连接故障暂停 30 秒；明确的限流立即暂停 30 秒，认证拒绝暂停 30 分钟。参数错误、型号不存在和客户端主动断开不计入连接故障。暂停结束后只允许一个恢复请求；仍在执行且有心跳的请求不会因初始探测租约过期而重复探测。较早请求的迟到结果不能覆盖更新的暂停状态。

管理页显示暂停状态和“恢复连接”；保存连接时也会重置该状态。恢复只是允许下次请求检查上游，不发起额外付费探测。外部 relay API 和内置助手复用同一路由与账本。

此实现是一主一备和共享熔断基础，不包含多层优先级、权重负载均衡、主动健康探测、任意模型替换或供应商账单自动对账。

## 兼容范围

支持文本消息和文本分段、`system`/`developer`/`user`/`assistant`/`tool` 角色、完整的工具结果往返、单个生成结果、采样参数及输出上限。OpenAI 兼容上游可传工具选择、严格工具定义、JSON/JSON Schema 输出、推理参数等；具体是否支持仍取决于所选上游模型。

外部接口暂不支持图片、音频、Responses、Embeddings、Batch。原生 Anthropic/Gemini 的高级参数只支持已映射的采样选项；不支持的字段明确返回错误，避免被悄悄忽略。OpenAI 兼容上游使用实时 SSE；原生 Anthropic/Gemini 当前取得完整结果后封装为 SSE。

字段约定参考 [OpenAI Chat Completions 官方文档](https://developers.openai.com/api/reference/resources/chat)。这些边界不代表支持所有使用 OpenAI 接口的软件；例如使用 Responses 的客户端需要额外适配。

## 额度与重置

调用前按当前价格及输入、输出上限预留，完成后按实际上游用量结算。价格版本固定在调用上。缺少用量或无法确认结果的调用标记为待核对，保留账目预留，不自动重试。

本次修正：手动重置或使用重置卡后，所选周期的基础额度完整恢复。例如每周 1000 点，重置后基础剩余为 1000 点。原有历史费用仍保留，旧调用以后结算也不会占用新恢复的同一周期基础额度。

额外点数、额外点数预留、团队总额度和 Key 累计上限各自保留；仅重置成员周额度不会重置这些限制，也不会清空月额度。基础剩余与“本周累计费用”分别展示，待核对调用提供单独入口。

实现使用四个额度窗口的代次记录（团队/月、成员/月、团队/周、成员/周），重置与结算由现有数据库事务串行保护。旧调用默认属于代次 0，升级迁移不改动历史费用或已有余额。升级后再执行一次需要的重置，恢复完整基础额度。
