# 0.2.19：邀请加入、团队广场与独立浏览

## 账号和团队

- 首页集中提供我的团队、团队管理、软件管理和团队广场入口。
- 一个个人账号可以加入多个团队，也可以同时拥有不同团队。软件权限与团队权限分别授予。
- 软件管理员或获得“管理团队准入及规模”权限的软件开发者，可发放创建团队邀请码，预先设定人数上限、有效期并撤销未使用邀请。
- 新个人账号默认必须持有成员邀请码或创建团队邀请码。未来开放注册通过 `WORKBENCH_OPEN_REGISTRATION=1` 配置，目前默认关闭。
- 团队所有者与管理员可以给成员设置职务，并分别授权公告、成员邀请和招募管理。当前只提供这三项细分授权，完整自定义职位权限后续扩展。
- 加入团队、恢复停用成员和提升停用成员均检查成员上限；并发加入不能挤占最后一个名额。

## 团队广场

- 团队自主选择公开介绍、方向和招募职位。原团队默认不公开，不新增演示团队或演示成员。
- 用户可保存文字简历与作品链接，向职位投递。简历只展示给本人和所投递团队的审核人员。
- 团队审核通过后，申请人再确认加入，届时检查有效邀请和剩余成员名额；审核通过不预留名额。

## 好友与团队群

- 同团队成员无需好友即可私聊，不会自动成为好友。
- 跨团队私聊先申请好友；好友关系不随离开团队消失。
- 支持选择本团队成员建群，群主与群管理员独立于团队职位。
- 新增个人聊天与团队群首版支持文字发送、Enter 发送和消息刷新。既有团队消息保留附件、引用和点数功能；新增聊天暂未提供这些功能及未读提醒。

## AI 搜索和浏览

- 识别 benchmark 常见拼写错误，防止模型将用户主题改成搜索引擎名称，过滤无关的“百度一下”等首页结果。
- 桌面内置浏览器可放大、独立窗口打开、输入地址、前进后退、刷新与缩放。切换展示方式保留页面和历史，切换账号或团队清理隔离会话。
- 网页端正文预览可以放大；原网页通过新窗口打开。

## 升级与检查

服务端新增 core `0025_team_admission_recruitment` 和 `0026_personal_messages_team_groups`。原有成员、项目、实验、财务、API 密钥和点数保留；现有团队人数超过默认上限时，迁移保留足够容量。桌面安装不替代服务端升级。

Windows 本地通过 524 项 Django、52 项 Node、13 套 Electron 界面检查，另通过数据库迁移、桌面认证、积分并发和团队最后名额并发检查。实际公网搜索返回 benchmark 相关来源；没有调用付费模型。Linux、Windows 和 Mac 构建以对应 GitHub CI 为准，未进行 Mac 实机验收。

本轮继续使用开发分支与 PR，未配置 Preview、未部署正式服务器，也未合并或发布正式自动更新。

## 0.2.19 修订

- 桌面端允许尚未加入团队的账号进入团队广场和个人聊天，团队业务入口仍检查成员资格。
- 修复重复投递报错、编辑团队资料覆盖并发调整的人数上限，以及无效聊天游标导致消息先发送后报错的问题。
- 个人私聊与群聊按消息编号增量读取，避免时间戳回退造成漏消息；发送成功清除旧错误提示。
- 搜索拼写纠正支持中文相邻文字，搜索词细化保留完整英文主题词，避免子串匹配及多关键词丢失。
- 网页来源快速切换不会被旧响应覆盖，原生浏览器异常提供打开原网页入口。
- 网页子框架失败不会误报整页失败；独立浏览器快速打开、收起或销毁不会触发未处理异常。
- 好友接受和所有权交接先取得 SQLite 写锁，新增两项真实并发检查并纳入 Linux / Windows CI。

修订详情与证据见 [本轮复查记录](REVIEW_0_2_19.md)。
