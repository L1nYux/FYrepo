# 团队分层与 AI 联网读取（开发分支）

0.2.19 在多团队隔离与网页读取基础上加入邀请准入、团队规模、岗位授权、团队广场与好友及团队群，桌面浏览支持放大和独立窗口。未配置 PR Preview，未部署正式服务器；服务器升级由管理员执行，合并与公开自动更新发布另行决定。桌面升级不代替服务器的数据迁移和浏览器安装。

## 团队与账号

账号、邮箱、密码和头像属于本人；一个账号可以加入多个团队。项目、任务、实验、消息、附件、财务、API 连接、价格、积分、额度、个人 API Key、AI 历史和后台任务各自属于团队。

| 身份 | 权限 |
| --- | --- |
| 软件管理员 | 查看团队基本信息、启停团队；通过 Django 软件后台管理全局账号。不自动获得其他团队私有工作台权限。 |
| 团队所有者 | 管理自己的团队、邀请成员、交接所有权；不获得软件管理权限。 |
| 团队管理员 | 管理当前团队的成员、项目和业务。不能移除所有者，不能提升软件权限。 |
| 成员 | 使用当前团队的工作台和已授权的 API 池。 |
| 访客成员 | 访问公开内容；可以持相应邀请码创建或加入团队。 |

网页账户菜单、桌面账户菜单和设置均提供「我的团队」。默认注册需要成员邀请码或创建团队邀请码；创建团队邀请码由软件管理发放并预设人数上限。无邀请码个人注册配置默认关闭。默认先进入有效的成员团队；用户明确切换后保留选择。团队切换时清空桌面导航、未读数和来源浏览状态，AI 草稿与任务缓存按账号及团队分开保存。

停用或移出成员仅改变当前团队资格并吊销当前团队凭证；历史记录保留，其他团队不受影响。共享账号的密码涉及所有团队，团队管理员不能直接重置这种账号，也不能重置软件管理员；本人可通过绑定邮箱找回，软件管理员可在软件后台处理。仅属于当前团队的普通成员保留临时密码流程。

软件管理员由全局 `User.is_superuser` 判断；委派软件开发者可单独授予 `core.manage_team_admission`，管理准入及规模而不获得全局账号后台权限。团队权限由 `TeamMembership` 判断，职务与授权只作用于所在团队。已有管理员升级后保留原软件权限，原团队管理员资格单独迁移。新建团队不会修改 `is_staff/is_superuser`。可信旧导入和命令行 `createsuperuser` 保留原团队开户兼容；要创建仅有软件权限的账号，应通过软件后台创建账号并设置权限，不自动授予团队资格。

## 迁移与运维

团队隔离迁移为 core `0024_team_teammembership_and_more`、aihub `0016_alter_assistantimage_options_and_more`，本轮另加 core `0025_team_admission_recruitment` 与 `0026_personal_messages_team_groups`。原业务归入 ID 1 的「原科研团队」。账号主键、密码摘要、邮箱、附件路径、历史业务关系与余额保持原值；首个有效软件管理员（没有时取首个有效旧团队管理员）成为原团队所有者。升级前仍须备份数据库、附件及私有 API Key 文件。

日常 HTTP、ASGI、AI 后台任务和个人凭证都带团队范围。个人 API Key 按创建时的团队和实验执行，不随浏览器切换而改变。价格维护、红包过期退款和发布公告维护逐团队执行；`set_api_owner --team ID 用户名` 可指定团队。可信旧命令默认 ID 1；新运维代码应使用 `core.tenancy.scope(team)` 明确选团队。

厂商密钥存储仍以全局唯一 Provider 主键分开。原团队保留旧环境变量兼容；新团队若使用环境变量，必须采用 `WORKBENCH_TEAM_<团队ID>_` 前缀，不能读取其他团队或宿主的通用密钥。

## 搜索与网页读取

- 默认优先使用 [Exa 官方免费 MCP](https://exa.ai/docs/get-started/exa-mcp) 的公开搜索工具，只发送搜索词，不发送完整工作台资料或厂商 API Key。免费入口有限流，不承诺无限可用；被限流或无相关结果时切换 Bing、百度、DuckDuckGo 公开来源。可保留 `WORKBENCH_SEARCH_URL` 自定义搜索入口。
- 明确要求搜索或读取某个地址时，先实际执行只读工具再让模型回答。搜索后自动尝试读取两个原网页。所有厂商共用这条流程；不支持原生工具的模型也能使用明确的搜索、网页读取请求。
- 支持多轮原生工具：最多 7 轮工具，最后一轮只生成答复；保留厂商要求的原生工具消息和推理字段。纯文字承诺、泄漏的工具 JSON 不当作成功执行，也不直接运行。
- HTML、文本、PDF 使用原有正文读取；JavaScript 页面可自动用 Chromium 渲染，模型也可选 `read_web(mode='browser')` 重新浏览。按真实读取状态显示进度、来源数量和正文引用；搜索摘要与已读正文有区分。点击来源打开右侧来源列表，桌面可在内置浏览器看原网页并返回列表。
- 读取失败仍显示失败与重试，不编造网页或引用。登录页面、验证码、站点封锁仍可能无法读取。自动化没有调用付费模型；厂商实际账号连接仍需在验收环境检查。

网页渲染使用临时、无登录凭证的 [Playwright Chromium](https://playwright.dev/python/docs/network)。Chromium 沙盒保持开启；HTTP 请求通过验证公网地址并固定连接 IP 的读取器，阻断内网、元数据地址、写请求及下载。WebSocket 仅在本地丢弃，不连接源站；备用代理阻止绕过读取器的网络流量。每页有限时、请求数、下载量和正文长度限制，最多同时渲染两页。

代理 DNS 返回 `198.18.0.0/15` 占位地址时，使用固定公网 DNS 的 TLS 查询取得真实 IP 后再次检查；占位 IP、内网 IP 和混合内网结果仍禁止连接。

## 运行环境与检查

开发环境安装 requirements.txt 后运行 `python -m playwright install chromium`。Linux 首次安装使用 `--with-deps`。服务器安装/升级脚本会准备独立 `.chromium` 并设置运行路径，未执行本次部署。Ubuntu 的 AppArmor 限制用户命名空间时，安装脚本按 [Chromium 官方文档](https://chromium.googlesource.com/chromium/src/+/main/docs/security/apparmor-userns-restrictions.md) 为实际安装的、由 root 保管的浏览器可执行文件配置路径许可，保留系统全局限制和浏览器沙盒。不支持该配置的系统需另行配置适用权限；禁止通过关闭沙盒绕过。

运行完整回归时设置 `WORKBENCH_BROWSER_TESTS=1`；UI fixture 设置 `WORKBENCH_CAPTURE_UI=.test-scratch/render-pages`。Windows 工具隔离环境可能限制 Chromium 子进程，须在允许子进程的终端执行，浏览器本身的沙盒仍开启。

隔离检查：`tools/check_team_migration.py` 使用旧版本临时数据库验证升级；`tools/check_desktop_team_auth.py` 验证本地桌面初始化、邀请码注册及团队登录；`tools/check_point_gift_concurrency.py` 验证积分并发。以上均不读取正式业务数据或真实厂商密钥。

## 团队广场与个人交流

广场默认不公开，团队自主发布介绍与职位，个人简历只由本人和投递团队审核者查看。审核后申请人确认加入，确认时检查名额，不在审核时预留。原团队不新增演示数据。

好友与个人私聊属于个人账号；同团队可直接私聊，跨团队需双方确认好友。团队群只向显式群成员开放，群权限与团队职位分开。新增个人聊天与群目前仅支持文字和刷新，附件、红包、引用及未读提醒仍是原团队消息功能。
