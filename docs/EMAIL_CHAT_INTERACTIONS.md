# 邮箱验证与消息交互

## 邮箱

`账户资料` 的姓名与邮箱分别保存。邮箱只能经过发送验证码、验证成功后写入账户。`email` 字段即使随旧资料表单提交也不能直接绑定。已有邮箱保留，不要求老账户重新验证。

验证码以摘要存储，按 `reset` / `bind` 隔离。绑定挑战关联当前账户、浏览器会话、发送时的原邮箱与实际发送地址；验证码不能用于另一会话、另一账户或密码重置。更换邮箱成功后原邮箱重置码失效。并发邮箱占用由数据库唯一索引及提交时检查处理。

找回页面使用三步验证码流程。验证成功时消费验证码，并在服务端会话保存一个短期重置授权；授权关联账户、邮箱、密码版本。密码或邮箱被另一次操作修改后，该授权失效。已有合法密码重置链接兼容保留，新页面不再发送链接。

需要服务器配置现有 SMTP。迁移：`core.0018_email_binding_code`，仅添加验证码用途，无账户数据清理。

## AI

助手的 OpenAI 兼容接口启用流式请求，读取正文、`reasoning_content` / `reasoning` / `reasoning_details`、MiniMax `<think>`，拼接工具调用和最终用量。工具后续请求保留厂商完整 assistant 消息；思考文本不会混进最终正文。

进度最多约每 400ms 写入任务，前端约每 700ms 读取，实时显示状态、文字及可折叠思考内容。Anthropic/Gemini 原有非流式调用继续可用，若返回可展示思考文本会在完成后显示。不会自动强制开启模型思考或修改模型推理预算。

服务端请求限制响应大小、行长度和总时长，拒绝跟随带凭证的重定向。厂商忽略流式但直接返回 JSON 时在同一次请求内处理。缺少结束标记、断流或用量缺失保留费用待核对；不自动重发付费请求。

供应商参考：

- [千问流式输出](https://help.aliyun.com/zh/model-studio/stream)
- [MiniMax OpenAI 兼容接口](https://platform.minimax.cn/docs/api-reference/text-openai-api)
- [GLM 流式调用](https://docs.bigmodel.cn/cn/guide/models/text/glm-5)（使用其原生流式字段，不强加额外的 `stream_options` 参数）

## 快捷键

`static/core/composer.js` 共用发送规则；会话输入框以 `data-message-input` 标记，长正文不标记。只在精确指针且可悬停的设备上启用 Enter，排除组字和键盘重复事件。原生表单提交仍执行必填与格式检查。

这一更新在服务端页面和资源生效，现有 0.2.7 桌面壳可直接加载，不需要用户重新安装。
