# 0.2.3：统一 Plan、点数和加载反馈

## 使用方式

负责人在 API 池管理 → 用量与额度中使用两个表单：

1. **每人每周点数 → 保存统一 Plan**：同一额度应用到全部现有成员，以及以后加入的成员。没有个人 Plan 调整入口。
2. **额外发放 → 所有成员或一个成员 → 点数 → 发放**：全员发放时输入的是每个人收到的点数，包含负责人本人。额外余额跨周保留。

成员列表只显示本周实际用量、基础剩余与额外可用点数，不需要逐人填写。

**重置全员本周额度**恢复所有在职成员的基础额度；不补回已经消费的额外点数，不删除调用与发放记录，不解除团队总预算限制。

## 规则

- 1 点 = ¥0.01；1000 点 = ¥10。
- 模型与用途不限制。AI 助手、成员 API 凭证调用共用个人点数，按调用时价格版本、实际输入/输出与缓存费用折算人民币。
- 内部人民币账单保留 8 位小数，不对每次调用向上扣整点。界面点数是成本 × 100。
- 先用基础额度，再用额外点数；调用前预留，结算时释放未用预留。明确未计费的失败释放额度；用量缺失的调用保留预留，等待负责人核对。
- 结算使用当时可用基础额度，在并行调用释放预留后优先使用基础额度；跨周调用结算回发起调用的预算周。
- 每周一 00:00（Asia/Shanghai）切换预算周，基础额度不累计；额外余额独立保存。
- 修改 Plan 立即应用到所有成员，但保留本周已用费用与执行中调用的预留。降额度不倒扣已经发生的费用。
- 发放记录带幂等凭据，同一表单请求重复提交不会重复充值。
- 团队总周/月预算与单次预留上限折叠在“团队总预算（可选）”。给成员发点不会自动提高供应商余额或绕过团队预算。

## 升级与兼容

- `aihub.0006_point_credits` 新增额外余额、调用分摊和发放记录。原账户、密钥、调用成本与财务记录保留。
- 原本已配置的默认周额度作为统一 Plan 保留；未配置的统一为每周 1000 点。负责人可设置其他整数点数，0 点表示没有基础额度（仍可用额外点数）。
- 历史个人周/月限额字段保留以兼容旧数据库，0.2.3 不再使用其个人覆盖值，全部成员按统一周 Plan 执行。
- 原有团队总预算保留。默认月度个人限额不再额外阻断周 Plan。
- 后端升级须使用保留数据的升级脚本；安装桌面客户端不会修改服务器数据库。请停止服务再迁移，勿用本地数据库覆盖服务器数据库。
