# 合并版交接

基线：GitHub `main` 的 `ef9fe627046aecc7e12f8c9acb5c8f15df61f965`。
本地分支：`codex/integrate-workbench`。目前为本地审阅版本，尚未部署或推送。

## 合并后的行为

- 访客默认进入公开首页。项目摘要、实验记录须经管理员公开；成员资料由本人主动选择公开。
- 右上角统一登录和邀请码注册。账号权限由服务器确定，无需选择登录身份。关闭普通用户自由注册；已有普通用户保持受限。
- 公告栏、项目管理、实验库、财务服务、个人信息、修改密码组成内部导航，保留仓库聊天室与财务功能。
- 项目 → 母任务 → 子任务，任务支持多名协作成员。开发者查看全部任务进度，向被分配的任务提交成果；项目负责人和管理员可以介入。
- 项目成员可拆分子任务；子任务参与者可以自主结项，母任务由项目负责人审核，项目最终结项由管理员操作。
- 成果支持文字、多附件、源码链接和多条实验引用；至少提供一项即可。源码附件仅保存和下载，不执行、不解压。每次最多 5 个文件，每个 20 MB，总计 40 MB。
- 实验库记录条件、数据来源、模型、Prompt、结果、人工评价及 Git 引用。实验不另设任务结项流程，公开审核仅决定访客是否可见。
- 管理员维护团队邮箱、电话、GitHub 和合作说明。
- 删除项目或任务后从正常列表隐藏，下级任务一并不可访问。管理员或项目负责人可在回收站恢复其有权管理的记录。

## 数据库

沿用仓库的 `0001` 至 `0004`，新增 `0005_integrated_public_experiments`。
不要把旧本地分支的 `0002_project_tree_and_team_finance` 等迁移复制进来。

- 已使用 GitHub 迁移链的数据库：正常备份后 `migrate`。
- 仅需保留账号的旧版本：在新空数据库执行迁移，再使用 `import_accounts --source /path/to/old.sqlite3`。
- 导入保留账号 ID、原密码摘要、姓名、邮箱、启停状态、管理员权限及可映射的组权限；不会显示或重置密码。不导入旧会话，用户需重新登录。
- 如果目标已有用户，或者存在无法映射的自定义权限，导入会停止，防止覆盖或丢失权限。

## 服务器升级（本地审阅通过后执行）

`deploy/upgrade_accounts_only.sh` 针对现有默认安装：`/opt/research-workbench`、`/var/lib/research-workbench` 和 `research-workbench.service`。
它会准备新空库、停止服务、导入原账号，保留旧代码、数据库、附件及环境配置，然后启动新版。只导入账号；旧业务数据留在备份中。

将代码解压到独立发布目录，确认原环境依赖与 `requirements.txt` 兼容后执行：

```bash
sudo bash /path/to/new-release/deploy/upgrade_accounts_only.sh --apply-accounts-only
```

脚本对失败尝试恢复旧代码与数据，再启动旧服务。实际服务器升级脚本尚未在生产环境执行；执行后还需确认公网访问。备份目录是 `/var/backups/research-workbench/upgrade-时间戳`，需另存服务器外副本。
