# 正式更新渠道检查与修复

## 确认的原因

GitHub 最新正式版本仍是 v0.3.1。0.4.1 至 0.4.3 的源码/测试交付标记为 prerelease，不能被正式更新器选择。0.4.3 没有 latest.yml、Mac 安装包与 Mac 更新清单，不能直接改为正式版本。

Windows electron-updater 和未签名 Mac 的 GitHub latest 查询都使用正式渠道，且不允许降级。未观察到自动降级成功；已确认的是正式渠道仍返回旧版本。

## 实现

- 安装版高于正式渠道时显示两者版本，不再声称已是最新发布版本。
- 两端单元测试覆盖版本提示与禁止降级。
- Windows 和 Mac 构建后检查安装包、blockmap、清单与 SHA512。合并后的草稿还需要完整三种架构资产。
- 标签构建仅生成 draft，不能自动进入成员的正式更新渠道。
- 修复 Node 加载网页校验函数时提前引用 Electron 图标模块导致的异常。
- 更新与已确认团队规则冲突的旧测试，保留权限、容量、计费和历史数据保护测试。
- 恢复团队管理迁移到工作台后丢失的待审核申请提示。
- 群设置改用表单 action 属性原值，避免同名输入覆盖请求地址；服务端返回实际保存的成员偏好。普通群和团队群都验证昵称、免打扰、置顶、昵称显示、搜索、刷新持久化与失败回退。
- 普通群首次渲染使用群昵称并保留隐藏昵称偏好，保存后立即更新已有消息，置顶有明确列表标记。
- AI 完成后后台刷新模型目录保留本轮用量提示。

## 发布步骤

先在分支完成 Windows/Linux 应用验证和 Windows/Mac 打包，检查完整资产及同一提交版本，再准备版本草稿。正式发布必须在用户确认后执行。

不能通过启用 prerelease 更新、允许 downgrade 或跳过失败测试来绕过问题。生产服务器连接仍是用户确认的 HTTP 配置。

## 验证记录

本地桌面单元测试：72 项通过。完整 Django 回归：683 项，结果通过（3 项环境条件跳过）。全部 18 组 Electron UI 验证通过。新加群偏好后端测试通过，覆盖普通成员修改、成员间隔离、非成员拒绝、昵称渲染与轮询、置顶排序、免打扰通知计数。

上一提交的 Windows 和 Apple Silicon/Intel Mac 安装包构建及资产检查通过；应用回归唯一失败为旧测试中的错误会话归属断言，已修正并重新运行。包含本轮群修复的最终云端应用与安装包结果待补充。测试只使用隔离数据与模拟 API，不调用收费厂商接口。
