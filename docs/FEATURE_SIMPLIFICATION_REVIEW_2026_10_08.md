# 知域功能与导航精简审查

日期：2026-10-08。审查对象：本地 0.4.1 源码，含尚未提交的连接回滚和部署脚本修改。

本轮为源码静态审查和产品整理建议，没有修改业务实现、运行测试、安装客户端或更新服务器。以下“建议”不代表已经完成。

后续用户已确认先实施。具体已完成项和检查范围另见 [精简实施记录](FEATURE_SIMPLIFICATION_IMPLEMENTATION_2026_10_08.md)，下方保留原审查结论。

## 已确认的产品方向

- 团队研究协作为主，个人区域保留账号、资料、安全和应用设置。
- 取消个人手工记账、个人 API 池配置的产品入口和业务流程。
- 成员调用 API：团队必选，项目和实验可选；团队额度、补发点数和重置额度继续保留。
- 积分红包、人才市场两个入口继续保留；HR 招募、入队审核继续保留。人才资料编辑统一在“我”。
- 入队和团队群加人都要求 HR；所有者默认有 HR，管理员需单独授权；只有所有者可授予或撤销 HR。
- 团队容量是硬性上限。每条招聘有计划人数，正式入队人数达到计划后结束招聘。
- 当前连接方式按已确认的 HTTP 回滚方案处理。

### 另一个未落实的功能要求

`core/community_models.py:63` 的 `TeamOpening` 目前只有标题、描述、启用状态等字段，没有计划人数。不能把“人数已满自动结束”描述为已经完成。实施时要按正式入队计算招聘人数，并在实际入队时同时检查团队硬上限，不能只依赖页面按钮是否可见。

## 建议的导航结构

| 主入口 | 内容 |
| --- | --- |
| 工作台 | 团队选择、项目、文档、实验；团队管理放在所选团队下。比赛、采样按需要展开。 |
| 消息 | 会话、联系人、团队群、系统通知；积分红包保留在聊天中。 |
| AI 助手 | 助手对话、明确可见的“API 调用”；API 页面集中提供地址、个人调用 Key、可用模型、团队余额和用量。获授权人员在同一模块进入池管理。 |
| 发现 | 团队广场、人才市场、合作邀请、申请进度。 |
| 我 | 资料、人才资料编辑、账号安全、应用设置。 |
| 软件管理 | 仅平台管理人员可见：平台账号、团队容量、账号操作记录。 |

“仓库”是否降为项目中的高级功能、比赛与采样是否默认折叠，属于待讨论建议，本轮没有决定删除这些功能。团队管理放在工作台也是布局建议，不是已实施的导航规则。

导航修复应统一路由、模块归属、显示名称和权限判定。目前主进程、桌面页面、服务端上下文和网页模板分别维护映射；继续在各处单独补跳转，会使不一致再次出现。

## 可以合并展示，但不能混合业务的数据

- API 余额、额度和用量摘要集中展示；积分红包的领取、过期退款及团队授权逻辑保留。
- 人才市场用于公开发现人才，HR 招募用于团队招聘与审核，两者入口保留并明确用途。
- 共享文档、提交审核、实验附件分别承担可编辑内容、审批记录和文件存储职责。统一关联及查找入口，不能粗暴合并模型。
- 本地 Git 仓库与共享文档审批不是同一种功能；调整默认可见性不等于删除仓库数据。
- 团队财务与 API 点数不是同一本账。取消个人手工记账不影响团队财务记录或 API 消费日志。

## 建议实施顺序

1. 修复账户模板，消除软件管理正文重复入口，统一导航归属与返回行为。
2. 落实已确认删减：撤下个人记账和个人 API 池流程，将成员团队 API 调用集中到 AI 模块；同时修改后端校验及扣费上下文。
3. 补齐招聘计划人数及自动结束；继续处理在线状态、Windows 图标等未完成问题。这些属于修复，不靠增加功能解决。
4. 讨论专业模块的默认可见性，然后同步指南。

已有数据库、API 凭据和消费记录不能因导航精简被一起删除。服务器此前的主要磁盘占用来自历史发布目录；清理后发布目录从约 13 GB 降至 2.1 GB。界面精简本身不会带来同等磁盘收益。浏览器运行时复用和未来版本自动清理的本地脚本修改仍未部署。
