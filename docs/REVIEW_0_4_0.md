# 0.4.0 应用与功能复查

日期：2026-10-07。范围：导航、人才与招聘、项目协作、AI 隐私与经费、群管理、聊天输入、表情、软件管理及版本交付。

## 问题与处理

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| 项目名称被挤成一个大字 | 栏目图标的通用 CSS 规则误作用于资源标题 | 图标、标题、归属使用独立类；标题正常字号、单行省略、悬停完整名称 |
| 团队管理还选中聊天列表 | 页面只更换右侧内容，消息侧栏未区分功能区域 | 聊天、通讯录、团队分别确定标题、列表、选中项 |
| 多团队管理可能操作另一团队 | 表单与重定向依赖会话中的团队选择 | 表单携带明确团队编号；权限失效明确拒绝；返回保留团队 |
| 退出或解散后返回失效团队 | 重定向继续携带已经失效的团队编号 | 检查成员资格；失效时清除记忆并返回团队列表 |
| 软件管理仍显示项目侧栏 | 管理路由未归入桌面设置区域 | 软件管理使用账号、团队容量、账号操作记录侧栏；按权限开放 |
| 无团队或个人概览显示团队公告 | 公告列表与个人汇总共用查询和入口 | 默认汇总只显示待办与最近项目；明确选择团队时显示该团队公告 |
| 只有少量 emoji 和“支持 emoji”文字 | 重复自建精简表情列表 | 聊天、留言共用本地 Emoji Mart；中文搜索、分类、最近使用、肤色与收藏管理 |
| 群资料没有成员加减入口 | 只有单人菜单和其他页面的成员管理 | 普通群多选添加、移出；团队群使用入队邀请和带交接确认的移出流程 |
| 群成员操作会刷新整个聊天 | 操作成功后重载页面 | 只更新成员与会话列表，保留正在输入的内容和附件 |
| 收藏表情会连草稿一起直接发出 | 表情点击事件自动提交整个输入表单 | 表情先预览，可取消，按发送按钮提交 |
| 私聊发送时输入可能被覆盖 | 请求期间仍可更改文字、附件和重新编辑来源 | 创建发送快照后暂锁输入；失败保留内容与附件；成功再清空 |
| 草稿及表情偏好跨账号复用 | 存储键未包含个人身份 | 草稿、展开状态、最近表情等存储包含账号标识 |
| 更新后仍无法判断哪里是旧版 | 桌面与服务端只有一个含糊的版本提示 | 关于页分别展示客户端和服务端版本；老服务器不提供时明确显示未知 |
| 旧帮助文档仍要求邀请码 | 使用说明停留在 0.2.5 | 更新当前说明，旧说明移入历史文档 |
| 招聘与人才没有独立入口 | 功能依附团队管理，个人展示意愿不清 | 发现提供团队广场、人才市场、申请、邀请及个人资料；人才默认不公开 |
| 已批准申请还要申请人确认 | 主动申请与被动邀请共用入队流程 | 申请批准直接入队；定向 offer 则本人接受，均提供系统消息 |
| 合作需要获得整个团队身份 | 项目参与依赖团队成员资格 | 显式项目授权，限定项目资料、任务和成果，撤销及时失效 |
| AI 历史与团队付费混在一起 | 会话和调用使用同一个归属 | 历史迁回个人空间，任务单独保存扣费来源；团队无法读取个人正文 |
| 撤销 API 资格后运行中的助手继续扣费 | 只在开始时检查 | 每次付费调用前重查成员和池资格，已经发生的费用仍结算 |
| 先自付再申请补助缺少凭据 | 报销与个人调用没有关联 | 只提交模型、时间、费用快照；跨团队避免重复申请，正文保持私有 |

## 借鉴与复用

- [Emoji Mart 官方项目](https://github.com/missive/emoji-mart)：直接复用 5.6.0 的浏览器表情组件和 1.2.1 数据，不再自建 emoji 列表。默认是操作系统原生 emoji，未复制微信专有表情素材。
- [Unicode CLDR](https://cldr.unicode.org/translation/characters/short-names-and-keywords)：采用 48.2.0 的中文名称与关键词，补充中文搜索。
- [Fluent 2 导航规范](https://fluent2.microsoft.design/components/web/react/core/nav/usage)：参考分组、层级、选中状态与可读标题。
- [Element 群设置](https://docs.element.io/latest/element-support/matrix-rooms/managing-a-room-room-settings/)：参考群资料与权限管理的入口位置；继续使用本项目已有团队资格与交接逻辑。
- [Notion 分享与权限](https://www.notion.com/help/sharing-and-permissions)：参考成员身份与具体资源授权分开，合作只开放必要项目。
- [GitLab 项目成员](https://docs.gitlab.com/user/project/members/)：参考项目级成员授权、权限收回和组织成员资格分别管理。
- [Linear Inbox](https://linear.app/docs/inbox)：参考集中处理需要本人响应的通知，通知提供明确目的地。

组件与数据本地提供，不通过运行时 CDN 加载。固定版本、来源摘要、许可证保存在 `static/vendor/emoji-mart/`。

## 防止重复出现

1. 以路由决定功能区域；独立的图标与标题类避免导航样式互相污染。
2. 操作明确携带归属，服务端再次检查资格；失效不默默转向其他团队。
3. 团队默认群成员与正式团队资格保持一致；普通群独立管理。
4. 表情、成员选择和资源分支由共用组件处理，避免私聊、团队群、留言各自实现一套。
5. 资源分支接口只读、登录可见、按已授权空间查询，不更换全局空间。
6. 客户端、服务端、安装包与源码版本分别说明，避免“源码已改”等同“运行版本已更新”。

## 已完成的检查及限制

本轮使用隔离数据检查权限、邀请、申请、协作、隐私迁移、经费审批和旧功能兼容性。桌面渲染检查使用真实模板与本地 Emoji Mart，在隐藏 Electron 窗口检查六个页面、群成员入口、发送位置、明暗表情面板和脚本错误。最终通过数量见交付清单。

- Django 业务检查：585 项，582 通过，3 项需要单独 Chromium 网页读取环境，按配置跳过。
- 桌面单元检查：56 项全部通过，包括发现的申请页归属、团队设置、软件管理和更新下载。
- 六个真实模板页面渲染与明暗 emoji 面板检查通过；121 个 HTML 模板编译、Python 和 JavaScript 语法、Django 配置及迁移一致性检查通过。
- UI 检查使用测试账号与模拟用量，没有登录成员的真实账号。

新增 core 0040–0042、aihub 0019–0020 迁移。升级脚本先对副本迁移、再备份与正式切换。历史归属及旧申请迁移没有反向操作，回滚必须恢复备份数据库和旧版本目录。

付费模型调用使用模拟响应，未花费真实 API 费用；外部厂商、服务器 SMTP 和真实多人同时操作仍需部署环境验收。现金审批登记账目，不执行银行转账。学历及执照认证未实现。不能据此声称所有线上流程都已验收。

交付为 0.4.0 候选包，本轮未自动替换已安装客户端、服务器或公开发布渠道。

## 2026-10-07 部署修正

首次服务器准备在生产模式 collectstatic 阶段失败：Emoji Mart 上游 bundle 引用了未随包提供的 browser.js.map。之前的本地静态检查使用 DEBUG 模式，未执行生产模式的散列与压缩处理，因此漏检。

移除仅供调试的 sourceMappingURL 注释，不改变组件运行代码；来源文件及交付文件的摘要记录在 provenance.json。新增 ProductionStaticTests，明确使用 DEBUG=False 与 CompressedManifestStaticFilesStorage 收集全部静态文件，核验表情脚本、数据、中文翻译及 gzip 文件。保留严格引用检查，未跳过资源错误。

该错误发生在停止正式服务之前，日志中的迁移针对升级检查副本。修正后继续使用固定提交下载和备份升级流程，不反向迁移，也不手工修改正式数据库。
